# HassMind v1.2.9 — Zalo Mobile Rich-Text Polish

Date: 2026-10-04

## Goal

Polish the already-working v1.2.8 Zalo `msg + styles[]` transport for real mobile readability. The user confirmed rich text renders correctly in the Zalo client; the remaining issues were long wrapped bullets, inconsistent model emphasis, and underused status colors.

## Changes

### 1. Mobile-first Zalo generation prompt

The Zalo channel prompt now asks the model to:

- keep each bullet focused on one fact;
- split long comma-separated values into nested bullets/numbered items;
- keep bullets roughly under 90 characters when practical;
- use one relevant emoji in a structured main title;
- use short labels (`Nhiệt độ:`, `Cửa:`, `Điều hòa:`);
- color only the status/value, not entire explanatory sentences;
- omit Home Assistant entity IDs from the main summary unless they are useful or explicitly requested.

This reduces awkward wrapping on narrow Zalo screens while preserving technical details when needed.

### 2. Conservative automatic label emphasis

For list items, short prefixes ending in `:` are automatically bolded if the model forgot markup. Example:

```text
- Cửa phòng: Đang mở
```

is transported as plain text plus a `b` style over `Cửa phòng:`.

Long prose such as `Ngày 24 tháng 9 ... tương ứng với:` is intentionally not auto-bolded.

### 3. Conservative automatic status colors

When no explicit color overlaps a recognized status phrase, the transport adds:

- green (`c_15a85f`) for active/healthy/safe values such as `Bật`, `Đang đóng`, `Online`, `Sẵn sàng`, `Tốt`;
- orange (`c_f27806`) for attention values such as `Đang mở`, `Unavailable`, `Mất kết nối`, `Cần chú ý`;
- red (`c_db342e`) for `Lỗi`, `Cảnh báo`, `Nguy hiểm`, `Thất bại`.

Explicit `{red|orange|yellow|green}` markup from the model always wins; automatic coloring never overrides it.

### 4. Style-span compaction

Identical overlapping style spans are merged before UTF-16 conversion. This reduces redundant `styles[]` entries while preserving formatting semantics.

## Compatibility

- No database migration.
- No secret migration.
- No Zalo Server API change.
- Continues to send `message: {msg, styles}` to `/api/sendMessageByAccount`.
- v1.2.8 plain-text fallback behavior for HTTP 400/422 style rejection is retained.
