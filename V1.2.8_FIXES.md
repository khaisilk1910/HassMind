# HassMind v1.2.8 — Zalo Rich-Text Transport Fix

Date: 2026-10-04

## Root cause

v1.2.7 normalized the model response into the markup dialect supported by the Zalo companion service, but `ZaloClient.send_message()` still posted only:

```json
{"message":{"msg":"# heading ... **bold** ..."}}
```

That assumes `/api/sendMessageByAccount` parses Markdown before it calls `zca-js`. The observed Zalo UI showed the delimiters literally, proving that this path was forwarding `msg` as plain text.

## Fix

HassMind now compiles supported markup before transport and posts a zca-js-compatible `MessageContent`:

```json
{
  "message": {
    "msg": "Tiêu đề\nTrạng thái: Tốt",
    "styles": [
      {"start":0,"len":7,"st":"f_18"},
      {"start":0,"len":7,"st":"b"},
      {"start":8,"len":15,"st":"lst_1"}
    ]
  }
}
```

The visible `msg` no longer contains Markdown/color delimiters. Rich formatting is carried only by `styles[]`.

## Supported compiler syntax

- `**bold**` -> `b`
- `*italic*` and backticks -> `i`
- `***bold italic***` -> `b` + `i`
- `__underline__` -> `u`
- `~~strike~~` -> `s`
- `#` / `##` -> `f_18` + `b`
- `###` -> `b`
- `####`..`######` -> `f_13`
- `{red|orange|yellow|green}` -> official Zalo color style codes
- `{big}` -> `f_18`; `{small}` -> `f_13`
- unordered lists -> `lst_1`
- ordered lists -> `lst_2`
- 1..8 leading spaces/tabs -> `ind_$` with `indentSize`
- blockquote -> italic
- Markdown links -> URL text, matching the existing companion behavior

## UTF-16 offsets

`zca-js`/JavaScript measures text offsets in UTF-16 code units. Python Unicode character indexes do not match when emoji are present. v1.2.8 builds a character-boundary -> UTF-16 map before generating every `start`/`len`, preventing styles from shifting after emoji.

## Compatibility fallback

If an older Zalo companion server explicitly rejects the `styles` field with HTTP 400/422, HassMind retries once with the already-compiled plain `msg`. It does not retry ambiguous timeout/5xx failures to avoid duplicate messages. The fallback therefore loses rich styling but never exposes raw Markdown markers.
