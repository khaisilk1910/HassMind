# HassMind v1.2.7 — Home Assistant Action/TTS Transport Review

## Root cause fixed

`ha_tts_speak` previously called `config/entity_registry/list` over Home Assistant WebSocket on every automatic TTS-entity resolution. The Python `websockets` client defaults to a 1 MiB decoded-message limit; a large Home Assistant entity registry can exceed that and close the connection with `ConnectionClosedError: frame exceeds limit`. The TTS message length is unrelated to this failure.

v1.2.7 resolves TTS in this order:

1. explicit `tts_entity_id` supplied to the tool;
2. `WYOMING_TTS_ENTITY_ID` / Web Admin setting;
3. current `tts.*` entities from HassMind's live HA state snapshot/cache;
4. full entity registry only as a last-resort disambiguation when multiple TTS entities exist.

All HA WebSocket connections also use a configurable bounded `HA_WS_MAX_SIZE` (default 16 MiB, clamped to 1–64 MiB).

## Home Assistant action shape

HassMind now models Home Assistant actions as `target` + `data`. `HomeAssistantClient.call_service_raw()` flattens supported target selectors (`entity_id`, `device_id`, `area_id`, `floor_id`, `label_id`) into the REST `/api/services/<domain>/<service>` payload only at the transport boundary.

`tts.speak` is emitted semantically as:

- target: `tts.*` entity
- data: `media_player_entity_id`, `message`, optional `cache`, `language`, `options`

The generic `ha_call_service` tool also exposes `target` separately and no longer requires a non-empty `data` object.

## Action audit

- `tts.speak`: corrected target/data separation and discovery path.
- Generic HA allowed-domain actions: target/data separation added; policy unchanged.
- `notify.*`: data-only service call remains correct.
- `am_lich_viet_nam.convert_date`: response-only service continues to request `return_response`.
- `yt_dlp.search/get_job`: response-only; `return_response` retained.
- `yt_dlp.play/download`: optional response; `return_response` retained intentionally.
- `shopping_history.add/edit/delete`: typed service-data calls unchanged.
- `shopping_history/get_data`: custom WebSocket command unchanged; benefits from the larger bounded WS frame limit.
- automation/script config endpoints are REST config APIs, not service actions, and are unchanged.

## Operator recommendation

In Web Admin -> Integrations -> Wyoming Vietnamese TTS, set **Home Assistant TTS entity** explicitly (for example `tts.piper`). This is the fastest and most deterministic path.
